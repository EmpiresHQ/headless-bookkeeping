## Proxy set-up

- **Build:** own production build of `effb488`, unmodified (`index-Bx2QxDOq.js`, `index-DJUHFF8w.css`; built `index.html` has no `viewport-fit`), served by `vite preview`.
- **Browser:** Chromium 153.0.8010.12 (Playwright 1.63.0), headless Linux, `isMobile` + `hasTouch`, desktop-Linux UA. `display-mode: standalone` was **false** throughout and was not forced.
- **Sizes:** portrait 390×844 and landscape 844×390 via `setViewportSize`. "Rotation" means a layout resize with the sheet open. It is not a device rotation and involves no toolbar change.
- **Synthetic insets:** CDP `Emulation.setSafeAreaInsetsOverride`, with all inset and max fields set, re-applied after each resize. Values were chosen by the harness and are **not device-sourced**:
  - portrait: top 47 / bottom 34;
  - landscape: left 47 / right 47 / bottom 21 / top 0.

  Each configuration was run with "none" (override 0) and with "forced".

- **Data:** every `/api` and `/admin` request went to route fixtures reused from earlier QA runs, and other origins were aborted. The fixtures included entities, categories, an EE VAT-registered organization, one expense/document and bank statement 3 / transaction 9. Some reused fixtures answer mocked POSTs with 200.
- **Writes:** no financial submit CTA was pressed. The only non-GET request observed was **one** automatic `POST /api/bank-statements/3/propose-matches` on bank Tx page load, answered by the fixture. No request reached a real server. Page errors: 0.

**`env()` applicability** (probe element with `padding: env(safe-area-inset-*)`, `/books`, 390×844):

| Phase                                              | Computed env t/r/b/l | TabBar height / padding-bottom |
| -------------------------------------------------- | -------------------- | ------------------------------ |
| No override, product meta                          | 0/0/0/0              | 55 / 8                         |

**Applicability gap:** the override yields the same computed values with and
without `viewport-fit=cover`. So the harness cannot show what a real browser

reported these insets to this page. CDP draws no occlusion, so hit-tests pass
even inside a band.

## Findings

No defect was reproduced, and there is **no confirmed native overlap**. That
is not a blanket all-clear.

1. **Conditional forced-inset geometry.** Surfaces with no `env()` term place controls inside the synthetic bands:
   - the lightbox top bar (portrait top band, landscape right band);
   - the source Verify sheet in landscape (root's run);
   - page headers (top band).

   Whether a real platform reports such insets to this page and lays content under them is unmeasured (rows B1–B2, L1–L4, S2–S4). There is no priority and no fix.

2. **Bottom handled as coded:** TabBar, main padding and ActionBar follow `--tabbar-h`. Under forced bottom insets, TabBar links, Organization Save and the ActionBar CTA stayed above the band and were hit-testable.
3. **The form sheet has no safe-area contract.** Its CTA cleared the forced 34/21px bands with this fixture's layout and the fixed 24px padding, which is no safe-area guarantee.
4. **Landscape room:** at 844×390, the New expense CTA needs a sheet scroll (273 of 570px). It is reachable. Real landscape heights with toolbars are unmeasured.
5. **Harness caveats:**
   - The `/books` list fixture was empty (portrait max scroll 0), so that page's scroll-end evidence is weak. The Organization full page was added in a second run on the same build and server for max-scroll clearance.
   - A source-sheet measurement was removed before running, because root covered it.

## Reproduce the proxy

The scripts were ephemeral and are not committed.

1. Build `packages/web` and serve it with `vite preview`.
2. In Playwright Chromium, create a context with `isMobile`, `hasTouch` and a token in `localStorage.bk_api_token`. Route `/api` and `/admin` to fixtures and abort other origins.
3. After each `setViewportSize`, call CDP `Emulation.setSafeAreaInsetsOverride({insets:{top, topMax, bottom, bottomMax, left, leftMax, right, rightMax}})` with every field set; unset fields become undefined. Verify the computed `env()` on a probe element.
4. Measure the `[data-tabbar]` and open `[data-vaul-drawer]` rects, the named controls' rects, the `elementFromPoint` at each centre, and the document's maximum scroll.
