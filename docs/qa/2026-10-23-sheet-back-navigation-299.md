## Environment and steps

- Own worktree `/root/.cache/hbk-worktrees/issue-299`, branch `qa/299-sheet-back-navigation`, own dependencies and `data/qa-299/app.sqlite`; Node 24.21.0. No other agent's process, port, dependencies or worktree was changed.
- Linux headless Chromium **153.0.8010.12**, Playwright **1.64.1**, DPR 1, `isMobile` and `hasTouch`, CSS viewports **390×844** and **844×390**. These dimensions do not represent a physical phone or browser chrome.
- Production web build on port 5299; actual HTTP forwards to isolated Nest/SQLite on 4299. No Playwright API response mocks. Inference providers are deterministic substitutions but manual expense creation never calls them; intake polling and cron are disabled. No production/external account is involved.
- Fixture: 20 synthetic suppliers, long names; chooser renders eight and makes New expense genuinely scrollable. Books → Settings → Books establishes a real prior SPA history entry; Books → Add to the books → New expense opens the Sheet. Category unset for clean/dirty, dirty Gross `12.34`; pending category `software`, Gross `45.67`, VAT `0`, tax point `2026-09-10`.
- Pending response is held by the HTTP proxy **after** the real backend returns 201 and commits the draft. This tests a pending client with a committed server operation, not a suspended backend transaction. Releasing delivers the original real response.
- Forms are scrolled to the bottom. Final gesture probes wait for opening/layout stabilization. CDP `Input.dispatchTouchEvent` sends touchStart, 15 touchMoves at 25ms, touchEnd; coordinates, actual travel, delivered events and intermediate transforms are saved. The application is never patched to force drag behavior.
- `page.goBack()` drives H1/H2/H8. H3/H4 call two `history.back()` in the same JS task; H7 separates them by 100ms. H5/H6 use forced Playwright double-click on Close. Neither scripted history nor Playwright browser Back is evidence of a native OS edge gesture.
