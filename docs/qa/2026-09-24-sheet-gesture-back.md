# QA-006: Sheet swipe, system Back, dirty/pending and double close (issue #299)

This is a verification task, not an assumed bug. The run was a bounded, mocked
Chromium proxy matrix on `main` `9d6b5b7`. No product code was changed. **No
physical device, OS keyboard, real swipe or native system Back was used.**

**Issue #299:** one defect was found, and only with synthetic same-task input: #370. Root ran 3 touch-drag and 6 rapid-Back configurations; this run adds the matrix below. The 7 modal checks from #366 are cited, not rerun. Real-device swipe and native Back **remain NOT RUN**, so this is **not** an all-clear.

## Set-up

- **Build:** own `vite build` of `9d6b5b7`, unmodified, served by `vite preview` on `127.0.0.1:5364`.
- **Browser:** Chromium 153.0.8010.12 (Playwright build 1243), headless, driven by Playwright 1.63.0, on Linux. Context: `isMobile` + `hasTouch`, DPR 1, at 390×844 and 844×390. These are CSS viewports without browser chrome, not devices.
- **Mocking:** `/api` came from the shared fixtures (`/tmp/hbk-265-browser/fixtures.mjs` → 263 / 260 / 252), imported read-only, and other origins were aborted. The final targeted runs logged non-GET `/api` requests with `page.on('request')`; the initial run recorded POSTs through the fixture's `fault.calls`. **Each pending case sent exactly one held `POST /api/expenses` to the mock; every other case sent none.** No page errors occurred. No real token or service was used.
- **Data:** New expense (Books → Add to the books → New expense). Dirty = Gross `12.34` (focus case `7.00`). Pending = Gross `45.67`, date `2026-09-21`, category `office`, Create expense, with the mocked POST held open. The mocked success is `/books/expenses/24`. Verify = `/inbox/doc/12` → "Review extracted data" (sheet "Classify").
- **Harness:** `.review-299/gesture-matrix.mjs` (untracked). Results: `gesture-results-initial.json` (first full run, kept), `-rerun.json` (after the measurement fixes), `-gap0.json` and `-controls.json`. Screenshots are in `.review-299/shots/`.
- **Touch proxy:** `Input.dispatchTouchEvent` start, 15 moves ×30 ms, end. Capture-phase listeners counted the events that were actually delivered. The drawer's `translateY` was sampled mid-drag and at its peak with a CSS query (`[data-vaul-drawer]`), which also works while the question aria-hides the Sheet. Content drags are clamped to `innerHeight − 8`, and the travel actually delivered is recorded.

## Same-task double Back (gap 0), synthetic

Steps: open the Sheet, then run `history.back(); history.back()` in **one** `page.evaluate`. The fixture's history is `/books/expenses/12` (loaded by `goto`) → `/settings` (loaded by `goto`) → `/books` (link).

| Case                                                                       | Address after        | Screen after                                                                                                             | Next step                                                                                                                                                                            |
| -------------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Control: no Sheet                                                          | `/books/expenses/12` | "Expense" (both traversals applied)                                                                                      | —                                                                                                                                                                                    |
| Clean Sheet                                                                | `/settings` idx 0    | heading "**Books**", Sheet closed (still after 2.5 s)                                                                    | —                                                                                                                                                                                    |
| Dirty Sheet                                                                | `/settings` idx 0    | "Books", Sheet + question, `12.34`                                                                                       | Keep editing: Sheet kept at the `/settings` address. Discard: Sheet closes, still `/settings` with "Books". The next Back → `/books/expenses/12` (skips the real `/settings` screen) |
| Pending Sheet                                                              | `/settings` idx 0    | "Books", Sheet open, live region: "Failed to fetch · Creating the draft expense was not confirmed — your input is kept…" | The mock was released: still `/settings`/"Books", never reaches #24. 1 POST was logged by the mock. Next Back → `/books/expenses/12`; Forward → `/settings` "Settings"               |
| All in-app history (`/books`→`/settings`→`/books`, idx 2), dirty / pending | `/books` **idx 0**   | idx 2's Sheet (question / pending Sheet)                                                                                 | pending: the same "Failed to fetch" with no cross-document entry involved                                                                                                            |

So a same-task double Back leaves the address/`history.state` one or two entries behind the rendered route. With a held save, the page reports "Failed to fetch", and `books/create.tsx:144` shows the existing "not confirmed — your input is kept" warning. The input stayed in the form, and the mock logged one POST. **What rejected the fetch, and the root cause, are undetermined:** "Failed to fetch" alone does not identify an abort or its source. Neither gap 100 ms nor gap 400 ms reproduces this, and no physical-device reproduction was attempted.

**Independent reproduction (root, `/tmp/hbk-299-browser/rapid-results.json`, `rapid.log`).** History was built only from in-app links: `/books/expenses/12` → Settings → Books (idx 2), with no extra `goto`.

- **Pending, gap 0:** the address becomes `/books/expenses/12` idx 0, but `ReactRouter.state.location` stays `/books` and the Books Sheet stays open. After release, the mismatch remains: exactly 1 POST, "Failed to fetch", and the existing "not confirmed / input kept" warning.
- **Dirty, gap 0:** the same mismatch, and it persists after Keep editing.
- **Pending, single Back / gap 20 / gap 100 ms:** the Sheet holds at `/books` idx 2, and release → `/books/expenses/24` idx 3.
- **Dirty, gap 20 ms:** stays consistent on `/books`, and the second Back dismisses the question.
- No page errors. Filed as [**#370 (P3)**](https://github.com/EmpiresHQ/headless-bookkeeping/issues/370), reproduced only with a programmatic same-task double POP; no physical Back claim.

**Root files for follow-up (by priority):** `packages/web/src/lib/unsavedChanges.tsx` `RouteLeaveGuard` (blocker `reset()` when a second POP lands while the first is blocked for a layer, around lines 376–425), then `lib/modalLayers.tsx`. For the unconfirmed save outcome, investigate what rejects the held request during the traversal.
