# Account-owned bank journal with LLM-decided source identity

Overlapping statements must refer to a canonical bank transaction journal owned by a real bank account, distinct from the chart-of-accounts Account; statements retain source occurrences rather than owning separate copies of movements. This replaces statement-owned transaction identity, despite the migration cost across reconciliation and settlement, because the same movement must share one financial state across imports (issue #399; grilling Q3, 2026-10-04).

The LLM decides which source identifiers are authoritative, extending the mapping responsibility in ADR-0031 instead of requiring a hardcoded provider identity policy (grilling Q5). Persist bank-specific mappings and source evidence, reuse mappings across the bank's accounts and currencies, and expose mapping view/edit/delete in Settings rather than invoking the LLM for every upload (Q8, Q12). Account assignment is independent of format mapping; each bank account has exactly one currency (Q16). This intentionally revises ADR-0031's fresh-inference/no-mapping-storage choices; these design choices were confirmed in the interview and subsequent review.

If a stored mapping fails, stop and let the operator delete it and explicitly generate a replacement (Q13). Editing/deleting a reusable mapping never reparses old records. Settings needs no version-management workflow; each import retains an audit snapshot of the rules actually applied. Correct an erroneous import by deleting the statement and importing again, respecting financial-history safeguards (clarified Q14). A repeat of an active import uses its retained interpretation; incompatible identity interpretations across overlapping imports require resolution (Q8).

Without an authoritative identifier, similarity creates a review candidate and never authorizes automatic merging; unresolved candidates cannot be financially processed. Incompatible financial facts for the same identity are treated as a mapping/interpretation error and stop the entire incoming statement. Validate the whole statement before activating operations or allowing reconciliation; retain source and diagnostics on failure, while existing journal operations remain unchanged (Q20/Q21). Suspected account mismatch or mapping failure likewise stops the import (Q11). Only bank-booked operations enter the journal. Card authorizations are holds, not transactions: preserve source evidence but create no canonical transaction or reconciliation item, and provide no CLI action to book/promote them. Unknown booking status blocks processing until corrected mapping or bank evidence resolves it. CLI resolution covers account assignment, mapping selection/correction, linking a duplicate versus confirming a distinct operation, and excluding an erroneous source row (Q6/Q15).

Deleting a statement retains source/audit history. Shared transactions remain active; solely sourced, financially unused transactions leave the working journal but remain in history. Financially used transactions remain active pending separate correction, which deletion must identify (Q7, Q10). Existing transactions whose real bank account is unknown retain their IDs and financial links until account assignment through CLI; they must not be automatically merged into new account-scoped imports before assignment (Q12).

These choices were agreed during the 2026-10-04 design interview and subsequent specification review. They describe intended behavior, not an implemented feature.

## Review follow-up (2026-10-04)

Explicit delete/reimport may automatically restore a solely archived, financially unused operation with corrected facts, preserving the old interpretation and audit (Q17). Validate statement integrity before activating operations or allowing reconciliation (Q20). Account assignment must not contradict an existing posted settlement without normal financial correction (Q18). A reconciliation reference may move between duplicate records with an audit entry when the existing posting remains correct, including its ledger account, currency and financial amounts; metadata relinking does not reverse or repost payment (Q19). Collisions discovered during legacy account assignment use the same repair safeguards rather than creating two active copies or overwriting financial history.

The whole-import stop for same-ID financial disagreement supersedes the earlier row-isolation/partial-import proposal (Q21). Additional financial fields supplied by a later source, including previously absent original-currency amounts or FX rates, remain source evidence and do not automatically enrich the canonical operation or change settlement calculations; required financial changes use explicit resolution (Q22).
