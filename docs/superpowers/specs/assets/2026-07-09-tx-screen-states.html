Транзакция: все состояния, до пикселя

Один экран `/bank/statements/:id/tx/:txId` — 90% времени оператора. Экран сам понимает контекст строки и открывается сразу на правильном действии: не оператор ищет функцию, а функция встречает оператора.

Маршрутизация: на что открывается экран

Порядок проверок сверху вниз; первое совпадение определяет главный блок экрана. Альтернативы всегда доступны ниже — маршрутизация выбирает акцент, не прячет опции.

Жесты, клавиатура, правки полей

Мобайл — список выписки
  • Тап — деталь транзакции (это основной путь, не свайпы)
  • Свайп вправо — primary строки: подтвердить предложение AI / «создать и сматчить» если prefill полный
  • Свайп влево — sheet «ещё»: Personal / Fee / Match вручную
  • Long-press — multi-select для bulk (создать N расходов / book N предложений)
  • Свайп никогда не необратим: всё с Undo-тостом
Мобайл — экран транзакции
  • Тап по kv-полю (категория, VAT, дата, поставщик) — bottom sheet правки этого поля; вернулся — кнопка пересчиталась
  • Тап по герою-сумме — ничего (сумма из банка неизменяема — это факт, не поле)
  • «Или»-строка — sheet с полным веером: Personal / Fee / Prepayment / Match вручную / Skip
  • После действия — авто-возврат в выписку, скролл на следующей не сверенной
Десктоп
  • Two-pane: список слева, транзакция справа; j/k — по строкам
  • Enter — primary текущего состояния · e — создать расход · p — personal · f — fee · m — match вручную · u — unmatch
  • Space — превью документа кандидата (peek, как Quick Look)
  • Чекбоксы кандидатов — кликом или 1…9
Состояния загрузки и ошибок
  • Кандидаты считаются на сервере — пока ждём: skeleton-строки, primary-кнопка disabled, «ищем кандидатов…»
  • Ошибка создания/матча — тост с текстом сервера + кнопка «повторить», строка остаётся не сверенной, ничего не «застревает»
  • Undo отработал — строка возвращается наверх, расход-черновик удаляется (он ещё draft — удаление легально)
  • Все мутации идемпотентны на сервере — двойной тап по кнопке безопасен, кнопка busy после первого

Правила ненаезда
  • Суммы не переносятся никогда: `flex:none; white-space:nowrap; tabular-nums` — жмётся всегда текст, не цифры
  • Заголовок/подзаголовок — одна строка + ellipsis; длинный контрагент обрезается, сумма и дата — нет
  • Правая колонка (`rend`) — `flex:none`, левая (`rmain`) — `flex:1; min-width:0` — классическая пара против наезда
  • Nav-титул зажат равными зонами по 88px — не прыгает между экранами
  • Action bar перекрывает контент градиентом — последняя строка списка дочитывается сквозь него при скролле
  • Тап-цели ≥44px везде: радио 22px визуально, но вся строка — кликабельна
  • Chip в hero — на отдельной строке (`mt 6`), не в одной строке с подписью

Инварианты экрана
  • Primary-кнопка всегда одна и всегда проговаривает результат с суммой.
  • Сумма и дата из банка — факты, не поля: их нельзя отредактировать нигде.
  • Остаток строки не теряется: N:M-математика всегда сходится в ноль (счёт / аванс / долг).
  • Ни одно действие не требует ухода с экрана: поставщик, категория, документ-политика — всё решается на месте.
  • Всё обратимо 5 секунд (Undo), кроме ничего — необратимых действий на этом экране нет вообще.
